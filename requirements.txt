# ── why these are pinned (2026-09-10) ────────────────────────────────────────
# These were unpinned "until anything is deployed". That turned out to be the
# wrong bar: the checkpoint SERIALISER's treatment of unregistered types changed
# under us between releases, and because a blocked type comes back as a plain
# dict rather than raising, the change was silent. An unpinned dependency whose
# behaviour the approval gate's durability depends on is not a deployment
# concern -- it is a correctness concern from the first run.
#
# `app.state.CHECKPOINT_TYPES` now registers our state types explicitly, so the
# behaviour no longer depends on the default. The pin is belt-and-braces: it
# makes a serialiser change show up as a deliberate upgrade rather than as a
# resumed run quietly losing its types.
#
# requirements-lock.txt (full `pip freeze`) is still owed and is NOT this file --
# it cannot be generated honestly until one machine has the local-model stack
# installed too. See TODO.md Hygiene.
